## What we learned about Gemini 3.1 Flash Lite

Eight runs of iteration surfaced a consistent set of rules about how this model responds to prompt changes:

1. **GOOD/BAD example pairs reliably land. Rule lists without examples often don't.** Every durable fix in this eval was a pattern-match example pair. Rules alone (even with enumerated alternatives) get partially followed or ignored.

2. **Every ban needs an explicit safe fallback.** Banning generic filler ("excited about the possibility") pushed the model toward fabrication when no safe alternative was given. Banning the default opener ("I'm a first-year at Wharton") only worked because the prompt provided 4 concrete alternative openings. If you ban something, name what the model should do instead.

3. **Sparse-mode is where hallucination lives.** Rich-mode outputs were consistently strong because the model had content to work with. Sparse-mode outputs needed multiple iterations of constraint tightening because the model, given nothing to say, invents things.

4. **The model follows the most recent/specific example it sees.** Leaving a "borderline but acceptable" example in the prompt (the Run 002 thank-you example with "the areas we touched on") caused the model to replicate that pattern. Examples must be clean, not aspirational.

5. **Background/identity fabrication is a distinct failure mode from format fabrication.** The model will invent the *sender's* background even more readily than the *recipient's* details. Both need explicit rules.
